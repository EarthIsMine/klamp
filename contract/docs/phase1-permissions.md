# Namespace Permissions

UserRegistry and PermissionedResolver are deployed as pinned VerifiableFactory proxies. The registry salt is the configured value, and the resolver salt is the configured value + 1. The proxy address calculation does not include the implementation address, so the two salts are kept separate.

- Setup operator: temporarily holds only REGISTRAR/SET_PARENT and admin on the registry root, and TEXT_ADMIN/DATA_ADMIN on the resolver root (the same values as the Sepolia team deployment). Upgrade permissions are never granted in the first place.
- tokens: fixed resolver, 0 token resource roles, maximum uint64 expiry. In the seal step, all of the operator's resolver roles, SET_PARENT and admin on the registry root, and all roles on the klamp.eth parent side are revoked.
- What remains after the seal: one registry root REGISTRAR and admin held by the operator. It exists to register hooks.klamp.eth in Phase 2, and cannot re-register tokens, replace the resolver/subregistry, delete, or change the klamp.eth linkage (`testKeptRegistrarCannotTouchTokens`). `Phase1Setup.finalizeHooks` registers hooks with 0 roles and then revokes this last permission (`testFinalizeHooksRevokesLastRole`).
- registrar: receives 4 **per-key** setter permissions on the Beta resolver (`pool` text and data, and `description` and `url` text, for all names) via `grantSetterRoles`. Beta has no per-name delegation, so the creator does not write to the resolver directly but calls the registrar's `setTokenText(token, key, value)`, and the registrar checks `creatorOf[token]` and the key (description and url only). After the seal, no one holds resolver root roles, and the registrar is not a proxy.

`SealPhase1` checks the chain, parent linkage, tokens resolver, a real UniversalResolver round-trip lookup and the expected number of permissions, then revokes the operator's permissions. Re-running when already sealed skips the revocation writes. Unexpected root/token role holders block the seal. It assumes trusted protocol implementations and a clean fresh deployment, and this code does not certify arbitrary external proxies.

This seal does not remove the ENS protocol's upper-level root permissions. Expiry or re-registration of klamp.eth, or a change to the upper-level linkage, can change name lookups. The one-time nature of the token mapping, the resolver write restriction and the persistence of the name path are separate guarantees. Renewal is managed as an operational procedure, and the SDK checks the namespace.
